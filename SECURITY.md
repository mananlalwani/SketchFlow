# Security policy

## Supported versions

Security fixes are applied to the latest released version. Development branches and unreleased commits are not supported deployment targets.

## Reporting a vulnerability

Do **not** open a public issue for a suspected vulnerability, credential exposure, or privacy incident.

For a public release, maintainers must enable GitHub private vulnerability reporting and publish a monitored security contact in the repository settings. Until that contact is configured, use the repository owner's private channel rather than filing a public report.

Include a clear reproduction, affected version or commit, impact, and any relevant logs with credentials, tokens, personal data, drawing content, and project/share identifiers removed.

## Disclosure and handling

Maintainers should acknowledge a report within five business days, provide status updates until resolution, coordinate a fix and release, and credit reporters only with their consent. Credentials that may be exposed must be revoked or rotated before publication or remediation details are shared.
